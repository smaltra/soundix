# Soundix: генерация звуков через fal.ai и ElevenLabs

Дата: 2026-09-28. Дополняет `2026-09-28-soundix-v2-design.md`.

## 1. Цель

Если в библиотеке CC0 нет подходящего звука, человек генерирует его по тексту прямо в Soundix. Готовый звук попадает в «My sounds» и работает как любой свой звук: прослушивание, каркас, экспорт в ZIP для агента.

Решение Scott: ключ пользователя. Каждый вставляет свой ключ fal.ai, генерация оплачивается с его баланса. У Soundix по-прежнему нет сервера: запросы идут из браузера прямо в fal.

Проверено 2026-09-28: `queue.fal.run` отвечает на preflight с `Access-Control-Allow-Origin: https://smaltra.github.io` для POST, GET и PUT с заголовком `authorization`. Файлы результатов на `v3.fal.media` отдаются с `Access-Control-Allow-Origin: *`. Без ключа запрос получает 401.

## 2. Интерфейс

В библиотеке рядом с «Add your sounds» — кнопка «Generate». Она открывает диалог «Generate a sound» для текущего события:

- **Prompt** — многострочное поле. Заранее заполнено по событию: `<название>: a short sound effect for a game UI`, плюс до трёх слов для поиска (`, like click, tap, button`). Текст можно менять.
- **Model** — список из двух моделей (§3), по умолчанию ElevenLabs.
- **Length** — ползунок от 0,5 до 5 с, по умолчанию 1 с.
- **fal key** — поле типа password и ссылка «Get a key» на https://fal.ai/dashboard/keys. Галочка «Remember in this browser» по умолчанию выключена (§6). Если ключ уже есть, поле свёрнуто в строку «Key ····abcd · Change · Forget».
- **Generate** — запускает генерацию. Пока идёт работа, кнопка показывает «Generating…», рядом «Cancel».
- **Результаты** — список звуков, созданных в этом диалоге: ▶, имя файла, длительность и «Use for <событие>». Новый результат проигрывается один раз, как при прослушивании. «Use» назначает звук событию и закрывает диалог.
- Короткая строка внизу: «Your key and prompt go straight to fal.ai; Soundix has no server. Generations are paid from your fal balance.»

Каждое нажатие Generate создаёт один звук. Повторное нажатие даёт ещё вариант.

Сгенерированные звуки лежат в паке «My sounds» с пометкой «AI»; во всплывающей подсказке строки — модель и промпт. Удаление работает как у своих звуков.

Без текущего события кнопка Generate неактивна: промпту не с чего начаться, и назначать результат некуда.

## 4. Запрос

Очередь fal через `fetch`, без новых зависимостей:

1. `POST https://queue.fal.run/<endpoint>` с `Authorization: Key <ключ>` и JSON-входом модели. Ответ: `request_id`, `status_url`, `response_url`, `cancel_url`, `queue_position`.
2. Раз в секунду `GET status_url` (с тем же заголовком), пока не придёт `COMPLETED`. `IN_QUEUE` несёт `queue_position` (сколько запросов впереди): оно показывается, только если это целое число от 0 до 999, иначе просто «In queue». `IN_PROGRESS` — генерация идёт. Сбой fal — это `COMPLETED` с полем `error`: ошибка «failed», сам текст fal не показывается. Любой другой ответ (не JSON, незнакомый статус) — сразу ошибка «failed» с пометкой `unexpected status` и `PUT cancel_url`, а не тихое ожидание. Через 2 минуты на всю цепочку — «timeout» с последним статусом в наших словах.
3. `GET response_url` → выход модели → URL файла.

Все запросы к очереди идут с `cache: 'no-store'`: опрос раз в секунду не должен получать из HTTP-кэша браузера старый `IN_QUEUE`.

**Где запрос.** Под кнопкой строка: `Waiting for fal.ai` → `In queue #N` → `Generating` → `Downloading` и время с начала запуска. При нескольких запросах говорит самый продвинутый. У ElevenLabs напрямую очереди нет: `Waiting for ElevenLabs`.

**Диагностика.** Сообщение об ошибке заканчивается скобкой: наш шаг (`submit`, `status`, `result`, `file`), HTTP-код самого ответа и хост из нашей константы (`queue.fal.run`, `api.elevenlabs.io`, для файла — `the file host`), например `(status: HTTP 405 from queue.fal.run)`, `(submit: no answer from queue.fal.run)`, `(after 120 s: IN_QUEUE, 2 ahead)`.

**Ничего из ответа сервиса не показывается.** Ни текст, ни значения тела ответа (fal и ElevenLabs: `detail`, `message`, `error`, `error_type`, `status`, адреса) в интерфейс не попадают: сообщения только наши, по категории (§7). Категорию код определяет по HTTP-статусу и сырому телу и дальше тело не передаёт. Так ключ не может вернуться в сообщение ни в каком виде (пробелы, регистр, экранирование, Base64, полноширинные символы), и списка кодировок не нужно.
4. `GET` файла без заголовка авторизации → Blob.
5. Blob декодируется, как свой звук. Если браузер не может его проиграть — ошибка «bad-audio».

Адреса статуса, результата и отмены берутся из ответа fal, а не собираются вручную: у моделей с длинным путём они короче endpoint.

«Cancel» делает `PUT cancel_url`, обрывает ожидание через `AbortController` и не сохраняет результат, даже если тот придёт.

## 5. Результат

- Файл сохраняется в IndexedDB как свой звук с полем `generated: { model, prompt }`; `model` — это endpoint.
- Имя файла: `<id события>-ai.<ext>`, при повторе `-ai-2`, `-ai-3`. Расширение берётся из `content_type` или из URL, запасное — `mp3`.
- Экспорт: файл идёт в ZIP как свой звук — как есть, при любом формате экспорта, с тем же предупреждением «Your own sounds go into the archive as they are». Обе модели отдают форматы, которые принимает Roblox (mp3, ogg).
- `soundix.json`: `source` у такого звука — `{ "own": true, "original": "<имя>", "generated": { "model": "<endpoint>", "prompt": "<промпт>" } }`. При импорте он, как любой свой звук, становится missing: сам файл в JSON не передаётся.
- `CREDITS.txt`: отдельный раздел «Generated with AI»: файл, модель, промпт, ссылка на условия модели. Это не CC0: права определяют условия модели и fal.
- `AGENT.md` и ссылки не меняются. Промпт в `AGENT.md` не попадает.

## 6. Ключ

- По умолчанию ключ живёт только в памяти вкладки и пропадает при перезагрузке.
- С галочкой «Remember in this browser» он хранится в `localStorage` под своим ключом `soundix:fal-key`, отдельно от набора. Рядом предупреждение: сохранённый ключ может прочитать любая страница на `smaltra.github.io`; безопаснее отдельный ключ fal с лимитом расходов.
- «Forget» стирает ключ из памяти и из `localStorage`.
- Ключ никогда не попадает в набор, историю отмены, ссылки, `soundix.json`, ZIP, консоль и сообщения об ошибках. Заголовок `Authorization` уходит только на `queue.fal.run`.

## 7. Ошибки

Каждая ошибка показывается в диалоге одной строкой, ввод при этом сохраняется:

| Причина | Категория | Текст |
|---|---|---|
| 401, 403 | key | The key was not accepted. Check it on fal.ai. |
| 402 или сообщение о балансе в теле | balance | Your fal.ai balance is used up. |
| 422 | input | fal.ai did not accept the request: check the prompt and length. |
| 429 | busy | fal.ai is busy. Try again in a moment. |
| другая ошибка сервера, сеть, CORS | network | fal.ai could not be reached. |
| 2 минуты без результата | timeout | fal.ai took too long. Try again. |
| `COMPLETED` с `error`, незнакомый статус, нет файла в результате | failed | fal.ai could not make this sound. Try again or change the prompt. |
| файл не проигрывается | bad-audio | The sound came back in a format this browser cannot play. |

К тексту добавляется диагностика в скобках (§4). Слов сервиса в сообщении нет никогда.

## 8. Устройство

- `src/core/generate.ts` (чистая логика, с тестами): таблица моделей, `promptFor(event)`, `inputFor(model, prompt, seconds)`, `audioUrlOf(output)`, `generatedName(eventId, taken, contentType, url)`, `falError(status, body)` → код ошибки.
- `src/adapters/fal.ts`: `generate(model, input, key, signal)` — очередь, опрос, отмена, скачивание Blob.
- `src/storage/fal-key.ts`: чтение, запись и удаление запомненного ключа.
- `src/ui/GenerateDialog.tsx`, кнопка в `LibraryPanel`, пометка «AI» в `SoundRow`, тексты в `en.ts`.
- `OwnSound` получает необязательное `generated`; `entries`/`export` пишут его в `source` и `CREDITS.txt`.
- `llms.txt` и README: одна строка о генерации через свой ключ fal.

## 9. Проверка

- Тесты `src/core`: вход обеих моделей, извлечение URL из выхода, заполнение промпта, имена файлов, коды ошибок, `source` и `CREDITS.txt` для сгенерированного звука.
- Браузер: fal подменяется через перехват сетевых запросов (очередь → статус → результат → файл), с настоящим ключом не проверяется — ключей у разработки нет. Проверяются успех, отмена, 401, таймаут, запоминание и удаление ключа, «Use for», экспорт с `CREDITS.txt`, отсутствие ключа в `localStorage` без галочки и в ZIP.
- Настоящую генерацию Scott проверяет своим ключом после публикации.

## 10. ElevenLabs напрямую

Решение Scott: кроме fal можно подключить свой ключ ElevenLabs и генерировать без посредника. Где этот раздел расходится с §2–§9, действует он.

Проверено 2026-09-28: `api.elevenlabs.io` отвечает на preflight `Access-Control-Allow-Origin: *` и `Access-Control-Allow-Headers: *`; без ключа `POST /v1/sound-generation` получает 401 с JSON.

**Провайдеры.** У каждой модели есть провайдер: `fal` или `elevenlabs`. В таблицу моделей добавляется строка:

| Модель | Провайдер | Запрос | Длина |
|---|---|---|---|
| ElevenLabs Sound Effects (ElevenLabs API) | `elevenlabs` | `POST https://api.elevenlabs.io/v1/sound-generation?output_format=mp3_44100_128`, заголовок `xi-api-key`, тело `{ "text", "duration_seconds", "model_id": "eleven_text_to_sound_v2" }`; ответ — сам MP3 | ползунок 0,5–5 с |

ID этой модели в `generated.model` — `elevenlabs:eleven_text_to_sound_v2`, чтобы его нельзя было спутать с endpoint fal. Ссылка «Price and terms» ведёт на https://elevenlabs.io/pricing, условия в `CREDITS.txt` — https://elevenlabs.io/terms-of-use.

**Интерфейс.** В списке Model модели сгруппированы по провайдерам: «fal.ai» и «ElevenLabs». Поле ключа относится к провайдеру выбранной модели: «fal key» или «ElevenLabs key», у каждого своя ссылка «Get a key» (https://fal.ai/dashboard/keys, https://elevenlabs.io/app/settings/api-keys), своя галочка «Remember» и свои «Change · Forget». При открытии диалога выбрана первая модель того провайдера, чей ключ уже есть (в этой вкладке или запомнен). Если ключей нет, выбрана первая модель fal. Строка внизу: «Your key and prompt go straight to the service you pick; Soundix has no server. Generations are paid from your account there.»

**Ключи.** Два независимых ключа: `soundix:fal-key` и `soundix:elevenlabs-key`, правила §6 для каждого. Ключ ElevenLabs уходит только на `https://api.elevenlabs.io` в заголовке `xi-api-key`.

**Запрос.** Один `POST`, ответ — Blob MP3, без очереди и опроса. «Cancel» обрывает запрос через `AbortController`. Через 2 минуты — «timeout».

**Ошибки.** Тексты §7 называют выбранный сервис вместо fal: «The key was not accepted. Check it on ElevenLabs.» и т. д. Нехватку кредитов ElevenLabs присылает как 401 с `detail.status: "quota_exceeded"`: это ошибка «balance», текст — «Your ElevenLabs balance is used up.» Тело ответа читается только для категории (например, «quota» в `detail.message` → balance) и не показывается.

**Устройство.** `GenModel` получает `provider`; `src/adapters/elevenlabs.ts` — запрос к ElevenLabs; `src/storage/fal-key.ts` становится `src/storage/api-keys.ts` с ключом на провайдера; `falError` становится `apiError` и читает оба формата ошибок.

**Проверка.** Тесты `src/core`: вход ElevenLabs, ошибки обоих форматов, выбор модели по имеющимся ключам. Браузер: ElevenLabs подменяется так же, как fal; проверяются успех, 401, `quota_exceeded`, отмена, раздельное запоминание двух ключей.

## 11. Варианты и история

Решение Scott: генерировать сразу несколько вариантов, например 10 кликов, и выбирать из них. К вариантам можно вернуться и передумать: переключиться с #7 на #8 хоть сразу, хоть на следующий день. Где этот раздел расходится с §2 и §5, действует он.

**Сколько.** Рядом с Length — поле Variants: любое число от 1 до 10; сколько выбрано, столько и генерируется. По умолчанию 1. Число и выбранная модель помнятся до перезагрузки вкладки (модель по §10 выбирается, только пока её не меняли). Кнопка называет число: «Generate» или «Generate 10». Строка внизу напоминает, что каждый вариант — отдельная платная генерация.

**Как.** Каждый вариант — отдельный запрос с тем же промптом; модели сами дают разные результаты (у Stable Audio seed случайный). Одновременно идут не больше трёх запросов, остальные ждут. Готовый вариант сразу появляется в списке. Кнопка показывает «Generating 4 of 10…». «Cancel» обрывает всё, что ещё идёт или ждёт. Ошибка ключа или баланса останавливает остальные запросы: они упадут так же. Если часть вариантов не удалась, под списком одна строка: сколько не удалось и текст последней ошибки. Первый готовый вариант запуска один раз проигрывается сам.

**История.** Все варианты сохраняются в IndexedDB (отдельная база `soundix-variants`) и остаются после перезагрузки. История привязана к ID события (`click`). Каждый раз, когда диалог открывается для события, в нём список всех вариантов этого события, новые сверху: номер (#1, #2, …), ▶, длительность, модель и промпт во всплывающей подсказке, «Use» и удаление (×). Вариант, который сейчас назначен событию, помечен «In use». Под списком «Clear» удаляет всю историю события после подтверждения. Вариант появляется только после того, как хранилище его записало; если оно отказало, запрос считается неудачным с сообщением «could not be saved in this browser».

**Выбор.** «Use» сохраняет вариант в My sounds (с именем по §5: `click-ai`, `click-ai-2`, …) и назначает его событию. Если перейти с варианта #7 на #8, #7 остаётся в My sounds: его может использовать другое событие или вернуть отмена (Ctrl+Z), удалить можно вручную. Повторный «Use» того же варианта не сохраняет его второй раз. Удаление варианта не трогает его копию в My sounds. После «Use» диалог остаётся открытым, чтобы можно было сразу сравнить с другими; закрывается он крестиком или Esc.

**Устройство.** `src/storage/variants.ts` — записи `{ id, event, n, blob, duration, generated, added, savedId? }` в IndexedDB; `savedId` — ID в My sounds после «Use». Сервис `variants` рядом с `own`: список, добавление, отметка «сохранён», удаление одного, очистка события, импорт. `src/core/generate.ts` получает `runLimited(tasks, limit, signal)` — не больше `limit` задач одновременно (с тестом).

## 12. Проект в ZIP: поделиться наработками

Решение Scott: поделиться своими наработками — звуками и вариантами — с другим человеком. Ссылка несёт только текст, поэтому носитель — ZIP из Export, который Soundix умеет открыть целиком.

**Экспорт.** В диалоге Export галочка «Include all variants (N)», видна, когда у событий набора есть варианты; по умолчанию выключена. С ней в ZIP добавляются файлы `variants/<ID события>/<n>.<ext>`, а в `soundix.json` — поле `"variants": [{ "event": "click", "file": "variants/click/3.mp3", "generated": { "model", "prompt" } }]`. В `AGENT.md` тогда строка: папка `variants/` — варианты, которые человек не выбрал; загружать их в игру не нужно. `CREDITS.txt` не меняется: он про звуки, которые идут в игру.

**Импорт.** Import (меню, перетаскивание, Ctrl+V с файлом) принимает и `.zip`. Soundix читает из него `soundix.json` по правилам JSON-импорта и дополнительно:
- свои звуки: если у события `source.own` и файл `file` лежит в архиве, файл добавляется в My sounds (с `generated`, если он есть), и событие получает этот звук, а не «missing»;
- варианты: каждый элемент `variants`, чей файл есть в архиве и чей `event` — допустимый ID, добавляется в историю этого события с новыми номерами после уже имеющихся;
- `AGENT.md`, `CREDITS.txt` и файлы библиотеки в архиве не читаются: звуки библиотеки берутся по ID, как при JSON-импорте.

Ограничения для чужих архивов: не больше 500 файлов вариантов и своих звуков, файл не больше 10 МБ; всё, что браузер не может проиграть, пропускается. Сообщение после импорта называет, сколько своих звуков и вариантов добавлено. Архив без `soundix.json` — ошибка «The ZIP has no soundix.json.» Как и JSON-импорт, архив заменяет набор, и «Restore previous» возвращает прежний; добавленные звуки и варианты при этом остаются.

**Устройство.** `src/core/project.ts` (с тестами): `variantsForExport(...)` → файлы и поле `variants`; `zipContents(json)` → проверенный список своих файлов по индексу события и вариантов. `src/adapters/zip.ts` получает чтение архива. `planExport` и `buildSoundixJson` принимают варианты.

**Проверка.** Тесты `src/core`: поле `variants` и пути в экспорте, строка в `AGENT.md`, разбор `zipContents` с мусором (чужие пути, недопустимые ID, лишние поля). Браузер: экспорт с вариантами → очистка хранилища → импорт этого ZIP → набор, свои звуки (играют, не «missing») и история вариантов на месте.

## 13. Диалог попроще (решение Scott после первой настоящей генерации)

Где раздел расходится с §2, §10 и §11, действует он.

- Сначала выбирается сервис переключателем «ElevenLabs | fal.ai», ElevenLabs первым. Точка у сервиса значит, что ключ для него уже введён. Список моделей виден, только если у сервиса их несколько (у fal.ai две). Без ключей выбран ElevenLabs.
- Soundix сначала очищает вставленный ключ (пробелы и переносы, кавычки, `export`, `NAME=` или `"NAME":` в начале, запятая в конце) и узнаёт его по виду: `sk_<hex>` с возможным `_residency_<регион>` или старые 32 hex — ElevenLabs, `<uuid>:<секрет>` — fal. Ключ уходит сервису, только если подходит именно ему; ключ неизвестного вида никуда не уходит, Generate заблокирован с подсказкой скопировать ключ заново. Ключ другого сервиса, вставленный в поле, уходит к своему сервису, и этот сервис выбирается с подсказкой. Если сохранённый ключ не подходит к выбранному сервису, показывается ошибка и Generate не запускается: ключ ElevenLabs не должен уходить в fal и наоборот.
- Ползунки в ряд: Length, Variants (1–10, вместо поля с числом) и для моделей ElevenLabs «Follow the prompt» — `prompt_influence` от 0 до 1 с шагом 0.05, по умолчанию 0.3, подписи «Freer / Stricter». Значение помнится до перезагрузки вкладки.
- Промпт по умолчанию: `Short game interface sound: <название> (<до трёх слов>). Clean, no music, no voices.` Под полем подсказка: писать по-английски, что звучит, какое настроение и чего не должно быть.
- Строка внизу называет сервис и число генераций: «Paid from your ElevenLabs account: 5 generations». Про отправку ключа — в строке под полем ключа.
- В списке вариантов вместо названия модели показан промпт, модель во всплывающей подсказке.

## 14. Общий пул сгенерированного

Решение Scott: звук, сгенерированный для одного события, может подойти другому. Где раздел расходится с §11, действует он.

- Внизу диалога — все сгенерированные звуки, от нового к старому, с переключателем «All generated · N | This event · N». Выбор помнится до перезагрузки вкладки, по умолчанию All.
- У звука, сгенерированного для другого события, в строке метка с ID этого события («Generated for click» во всплывающей подсказке). Номер #n остаётся номером внутри его события.
- «Use» назначает звук событию, для которого открыт диалог; в My sounds он сохраняется под именем этого события (`hover-ai.mp3`). «In use» помечает звук, который играет это событие.
- «Clear» удаляет то, что сейчас показано: все звуки или только звуки этого события. Перед удалением подтверждение; использованные звуки остаются в My sounds.
- Звук по-прежнему принадлежит событию, для которого он сгенерирован (`variants/<его событие>/`). В `soundix.json` у варианта `usedBy` — события набора, которые его играют, в том числе чужие. При импорте вариант получает связь с копией в My sounds первого такого события, и «In use» сохраняется. ZIP без `usedBy`, но с `used: true` понимается как «играет своё событие».

## 15. Моно

Решение Scott: сгенерированные звуки часто перекошены в одну сторону. Звуку интерфейса стерео не нужно, а в Roblox перекос остаётся.

- Галочка «Mono: the same in both speakers» в диалоге, по умолчанию включена, помнится до перезагрузки вкладки. С ней стерео-результат сразу сводится в моно: каналы усредняются и сохраняются как WAV, 16 бит PCM, с частотой декодирования. Громкость и разброс события не меняются.
- «Use» при включённой галочке сводит в моно и старый стерео-вариант, прежде чем сохранить его в My sounds.
- «Make all mono» над списком сводит в моно все сгенерированные копии в My sounds (то, что играют события) и все варианты, по одному. Копия сначала записывается, и только после успешной записи набор, резервный набор и вся история отмены переходят на её новое имя `.wav`. Каждый элемент отбирается по его собственным каналам, так что повтор доделывает то, что не удалось. Сообщение говорит правду: «2 of 3 made mono, 1 failed». Перегенерировать ничего не нужно.
- «Use» с включённой галочкой сводит в моно и уже существующую копию варианта, прежде чем назначить её событию.
- Экспорт берёт расширение своего звука по типу файла, а не по имени ссылки: сведённый звук уходит как `.wav`.
- При импорте ZIP события из `usedBy` одного варианта получают одну общую копию — копию первого из них, лишние записи в My sounds не создаются.

## 16. Запись в хранилище

Свои звуки и варианты меняются из нескольких мест сразу (Use, Make all mono, удаление, импорт), поэтому каждая запись подчиняется двум правилам.

1. Запись идёт только внутри очереди записи (`records.run(id)`), по одной на ID. Новая запись рождается там целиком (её ID ещё никто не знает) и появляется в интерфейсе только после удачной записи. Изменение существующей — патч к её текущей версии, прочитанной внутри очереди; целый объект из снимка, взятого вне очереди, не пишется никогда.
2. Результат каждой записи проверяется. Отказ — это отказ операции с честным сообщением: новый звук или вариант не появляется, Use не назначает звук, импорт считает всё, что не сохранилось (свои звуки и варианты), удаление, которое хранилище не выполнило, говорит, что звук может вернуться после перезагрузки. Отказ записи `savedId` ничего не теряет (связь держит копия) и потому не сообщается; отказ записи моно-файла варианта при Use — сообщается.

Связь вариант → копия в My sounds хранится с двух сторон: у варианта `savedId`, у копии `variant` (ID варианта), с которым она рождается одной записью. Копию ищут по любой стороне (`copyOf`), поэтому отказ записи `savedId` не делает вторую копию при следующем Use; при следующем Use этого варианта `savedId` дописывается. Импорт ZIP поэтому добавляет варианты раньше своих звуков.

Добавление ждёт первого чтения хранилища, поэтому номера вариантов продолжают сохранённые, а имена своих звуков уникальны среди них: перенумерации после загрузки нет. Удаление видно сразу: запись помечается удалённой, и ждущие в очереди изменения её не возвращают. Cancel или закрытие диалога во время записи нового варианта удаляют его сразу после записи, без автопрослушки. Отказ такого удаления сообщается общим тостом приложения, а не строкой диалога: диалог к этому времени может быть закрыт.

Одна копия на вариант: общий сервис `copies` (рядом с `own` и `variants`) держит «ID варианта → копия в пути». Use делает копию через него, а второй Use того же варианта ждёт первую. Импорт ZIP занимает замок для каждого варианта, который играет событие, с момента, когда вариант появился, до записи его копии, и отпускает его в любом исходе. Use во время импорта получает копию импорта, а не делает вторую.
