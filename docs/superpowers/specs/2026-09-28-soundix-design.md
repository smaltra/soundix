# Soundix: дизайн v1

Дата: 2026-09-28. Это решения Scott из обсуждения в чате, записанные вместе. Мелкие детали, которые добавил Head, отмечены «(деталь)».

## 1. Что это

Soundix — бесплатная веб-утилита. Разработчик заводит события своего интерфейса или игры и подбирает к каждому звук из библиотеки CC0 или свой. Звуки сразу слышно на макете интерфейса. На выходе он скачивает готовый набор: файлы с именами событий и JSON, модуль для Roblox или JS для веба.

Цель: выглядит просто, но экономит время. Scott делится утилитой со своей аудиторией (Telegram, X) и с другими разработчиками.

Принципы:
- всё работает в браузере: нет сервера, аккаунтов и аналитики, ничего не нужно ставить;
- только звуки с лицензией CC0;
- утилита универсальная, не только для Roblox.

## 2. Где живёт

- Репозиторий `smaltra/soundix`, публичный. Локально: `C:\Users\admin\Desktop\code\soundix`.
- Сайт на GitHub Pages: `https://smaltra.github.io/soundix/`.
- Лицензии: код MIT, звуки CC0. Авторы паков перечислены в приложении и в экспорте.

## 3. Экран

Шапка и три колонки: события, библиотека, «Проверить в деле». На телефоне колонки встают друг под другом. Прототип лежит в `docs/prototype/`: шаблон страницы и скрипт, который её собирал. Из него берём раскладку, клавиши и слова для поиска. Макет с плитками Smaltra («Магазин», «Индекс», «Коды») в Soundix не переносим.

### 3.0 Упрощение (решение Scott 2026-09-28)

Интерфейс показывает только главное, остальное появляется по требованию. Где разделы 3.1–3.4 расходятся с этим разделом, действует 3.0:
- в шапке на виду «Поделиться» и «Экспорт»; «Импорт» и «О звуках» в меню «⋯»; громкость прослушки — значок динамика с ползунком;
- карточка события в одну строку: название, выбранный звук, ▶. Ползунки громкости и разброса есть только у выбранного события, а название, имя файла и слова для поиска спрятаны под «Название, файл и слова для поиска»;
- библиотека открывается в «Подходящих»; ввод в поиск переключает на «Все звуки»; ★ и «Выбрать» появляются у строки под мышью (на сенсорных экранах видны всегда); полоса избранного видна, только когда в ней есть звуки; подсказка по клавишам — в значке клавиатуры;
- меток событий под элементами макета нет (решение Scott 2026-09-28): события элемента выбираются в «Изменить», в обычном режиме их показывает всплывающая подсказка.

### 3.1 Шапка

- Название Soundix.
- «Громкость прослушки», 0–100 %, по умолчанию 100 %. Нужна только для прослушки, в экспорт не идёт.
- Переключатель языка EN/RU.
- Кнопки «Поделиться», «Импорт», «Экспорт», «О звуках».

### 3.2 События (левая колонка)

Набор — это список событий. У события есть:
- название на любом языке;
- имя файла латиницей (`[a-z0-9_]`), уникальное в наборе. По умолчанию это транслит названия («Прыжок» → `pryzhok`), его можно поправить;
- звук из библиотеки или свой;
- громкость 0–100 %, по умолчанию 80 %;
- разброс высоты 0–20 %, по умолчанию 5 % (деталь: диапазон 0–20 %). В готовых наборах у `reward`, `level_up` и `purchase` стоит 0 %;
- слова для поиска: по ним работает режим «Подходящие».

Событие можно добавить, переименовать, удалить и выбрать текущим (клик по карточке). Карточка показывает звук (▶, имя, пак, ✕ «убрать»), ползунки громкости и разброса.

«Новый набор» заменяет текущий набор одним из готовых. Прежний набор сохраняется как резервный, появляется тост «Вернуть прежний». Несколько наборов одновременно в v1 не делаем.

Готовые наборы (деталь: состав наборов):

| Набор | События (имя файла — название) |
|---|---|
| Игра | click — Клик, hover — Наведение, open — Открытие окна, close — Закрытие окна, toggle — Переключатель, tab — Вкладка, notify — Уведомление, reward — Награда, level_up — Новый уровень, purchase — Покупка, error — Ошибка, locked — Закрыто |
| Приложение | tap — Нажатие, toggle — Переключатель, open — Открытие, close — Закрытие, notify — Уведомление, success — Успех, error — Ошибка, send — Отправка |
| Пусто | — |

Названия событий в готовых наборах пишутся на языке интерфейса в момент создания. Слова для поиска английские, потому что имена файлов в паках английские. Стартовые слова берём из прототипа (`EVENTS` в шаблоне) и дополняем тегами новых паков: `button`, `menu_select`, `fanfare`, `level up`, `coin`, `negative` и так далее.

### 3.3 Библиотека (центральная колонка)

- Режимы «Все звуки» и «Подходящие». «Подходящие» показывает звуки, у которых имя или теги совпадают со словами текущего события. Выше стоят звуки, совпавшие с более ранним словом в списке, при равенстве — более короткие.
- Поиск по имени и тегам, фильтр по паку, число найденных звуков.
- Строка звука: ▶, имя, длительность, ★, «Выбрать». У выбранного вместо «Выбрать» стоит ✓. Звуки сгруппированы по пакам.
- ★ Избранное: полоса сверху, чтобы сравнивать кандидатов.
- Клавиши: ↑/↓ — перейти к соседнему звуку и сыграть его, пробел — повторить, Enter — выбрать для текущего события, S — в избранное.
- Свои звуки добавляются перетаскиванием файлов на страницу или кнопкой «Добавить свои». Подходит любой формат, который играет браузер: WAV, MP3, OGG, M4A, FLAC. Они хранятся в IndexedDB и показываются паком «Мои звуки», их можно удалить.

### 3.4 «Проверить в деле» (правая колонка)

Изменено по решению Scott 2026-09-28: вместо заготовленных кнопок (магазин, награда и т. п.) макет собирается из событий набора и правится пользователем.

- Макет — список элементов в игровом стиле прототипа: яркие объёмные кнопки. Иконки встроенные SVG. Эмодзи не используем: 🪙 не рисуется в Chrome на Windows 10.
- Виды элементов и их срабатывания:

| Вид | Срабатывания |
|---|---|
| Кнопка | наведение, нажатие |
| Переключатель | переключение |
| Вкладки | смена вкладки |
| Ползунок | каждый шаг |
| Окно | открытие (кнопка), закрытие (✕ окна) |

- У элемента есть вид, надпись (у вкладок — названия вкладок через запятую), цвет из палитры прототипа (золотой, синий, зелёный, фиолетовый, красный, серый) и событие набора на каждое срабатывание или «без звука».
- У кнопки и окна может быть иконка из встроенного набора (монета, корзина, замок, подарок, колокольчик, звезда, сердце, кубок, галочка, крестик). Авто-макет подбирает её по имени события (`locked` → замок, `purchase` → корзина, `reward` → подарок, `notify` → колокольчик, `level` → звезда и т. д.), в «Изменить» её можно сменить или убрать.
- Пока макет не правили, он собирается из событий набора (деталь: правила): `toggle`/`switch` → переключатель, `tab` → вкладки, `slider`/`scroll`/`step` → ползунок, `open` и `close` → одно окно, `hover` → наведение первой кнопки, остальные события → кнопка с названием события. Цвет по имени: `error`, `locked` → красный; `reward`, `success`, `level` → зелёный; `purchase`, `coin` → золотой; остальные по кругу. Нет события — нет и элемента: без `purchase` нет магазина.
- Режим «Изменить»: у элемента меняются вид, надпись и цвет, элементы можно добавить и удалить. «Собрать из событий» возвращает автоматический макет. «JSON» показывает макет как JSON: его можно скопировать, поправить и применить. Неверный JSON — понятная ошибка, макет не меняется.
- В «Изменить» у элемента для каждого срабатывания выбирается событие набора или «без звука». Если событие удалили, выбор пишет «нет события». Переименование имени файла события переносит привязки.
- Пэдов нет: убраны по решению Scott 2026-09-28, событие слышно кнопкой ▶ в его карточке и на макете.
- На телефоне наведения нет, у кнопки с наведением об этом есть подпись.

### 3.5 Воспроизведение

Звук играет через Web Audio API (деталь). AudioContext создаётся при первом жесте пользователя. Буферы загружаются через fetch и decodeAudioData и кэшируются. Громкость равна громкости события, умноженной на громкость прослушки. `playbackRate = 1 + случайное число от −разброса до +разброса`. Один и тот же звук может звучать поверх себя, чтобы быстрые клики и наведения не обрывались.

### 4.2 Сборка библиотеки

- Исходники паков лежат в репозитории в `packs/<id>/` в том виде, в каком их скачали, вместе с файлом лицензии. Описание паков хранится в `packs.json`: id, название, автор, ссылка, лицензия.
- `npm run library` (Node, ffmpeg, ffprobe) собирает `public/library/`:
  - превью `<pack>/<путь>.ogg` в формате OGG Vorbis q5. OGG-исходники копируются как есть;
  - оригинал для экспорта, если исходник не OGG. WAV, MP3 и FLAC копируются, AIF и AIFF переводятся в WAV без потерь, потому что AIF не принимают ни Roblox, ни Godot;
  - `library.json`: версия формата, массив паков `{ id, name, author, url, license }` и массив звуков `{ id, pack, name, tags, duration, preview, original }`. У OGG-исходников `original` совпадает с `preview`;
  - id звука строится как `<pack>/<путь внутри пака без расширения>`: в нижнем регистре, пробелы заменены на `-`. Если все файлы пака лежат в одной верхней папке (`Audio/` у Kenney, `RPG Sound Pack/`, `The Essential Retro … By Juhani Junkala/`), эта папка в id и теги не входит. Примеры: `ui-audio/click1`, `voiceover-pack/female/congratulations`;
  - теги берутся из имён остальных подпапок, например `General Sounds/Coins` → `general sounds`, `coins`;
  - файлы с `preview` в имени, папки `__MACOSX` и скрытые файлы пропускаются.
- `public/library/` не коммитится: её собирает CI, а локально тот же скрипт.
- Громкость паков не выравниваем. Звук остаётся таким, каким его сделал автор, разницу закрывает ползунок громкости у события.
- Новый пак: папка в `packs/`, строка в `packs.json`, `npm run library`. Принимаем только CC0.
- Вес. Исходники в репозитории — около 73 МБ. На сайте около 28 МБ превью и около 55 МБ оригиналов (замер 2026-09-28: 512 Retro — 28 МБ WAV → 6,8 МБ OGG, RPG Sound Pack — 16 МБ → 1,7 МБ, Level Up 13 — 10 МБ → 0,5 МБ). При открытии страница грузит только `library.json` (около 200 КБ, в gzip около 30 КБ). Каждый звук скачивается при первом прослушивании.

## 5. Экспорт

- Окно «Экспорт» предлагает три вида: «Файлы + JSON», «Roblox» и «Веб». Формат файлов: «Оригинал» (по умолчанию) или «OGG (легче)» (деталь: переключатель формата). Кнопка «Скачать ZIP».
- События без звука в архив не попадают, окно об этом предупреждает.
- Свои звуки попадают в архив как есть в обоих форматах: браузер не кодирует OGG Vorbis, окно экспорта об этом предупреждает (решение Scott, находка SNDX-01 ревью Codex). Свой звук, которого больше нет в этом браузере, пропускается, а не ломает архив.
- Архив `soundix-<дата>.zip`:

```
sounds/<имя файла>.<ext>
soundix.json
CREDITS.txt
UISounds.luau + ROBLOX.md   только в виде «Roblox»
soundix.js + WEB.md         только в виде «Веб»
```

- Формат `soundix.json`:

```json
{
  "soundix": 1,
  "events": [
    {
      "id": "click",
      "name": "Клик",
      "file": "sounds/click.ogg",
      "volume": 0.8,
      "pitch": 0.05,
      "words": ["click", "tap"],
      "source": {
        "library": "ui-audio/click1",
        "pack": "UI Audio",
        "author": "Kenney",
        "license": "CC0",
        "url": "https://kenney.nl/assets/ui-audio"
      }
    }
  ]
}
```

  Для своего звука: `"source": { "own": true, "original": "my-jump.wav" }`. `volume` задаётся от 0 до 1, `pitch` — доля от 0 до 0.2.
- `CREDITS.txt` перечисляет только паки, звуки из которых есть в архиве: название, автор, ссылка, CC0. В конце строка «Made with Soundix — https://smaltra.github.io/soundix/».
- Вид «Roblox»:
  - `UISounds.luau` — ModuleScript. В нём таблица событий `{ id = "rbxassetid://0", volume = …, pitch = … }` и функция `UISounds.play(name)`. Sound создаётся в SoundService один раз, перед каждым проигрыванием ставится `PlaybackSpeed = 1 ± pitch`, звук играет через `SoundService:PlayLocalSound`. Пока ID равен 0, звук молчит.
  - `ROBLOX.md` объясняет, как загрузить файлы (Studio → Asset Manager или Creator Hub) и куда вписать ID. Там же ограничения Roblox (по документации на 2026-09-28): форматы mp3, ogg, wav и flac, файл до 20 МБ и до 7 минут, 100 бесплатных загрузок за 30 дней без проверки личности и 2000 с проверкой.
  - Громкость пишется как `Sound.Volume = volume`. При первой проверке в Studio сверить, звучит ли это как в Soundix.
- Вид «Веб»: `soundix.js` — ES-модуль без зависимостей. `const sfx = await createSoundix("./")` читает `soundix.json` и загружает звуки, `sfx.play("click")` играет звук. AudioContext запускается на первом жесте пользователя. В `WEB.md` лежит пример.

## 6. «Поделиться» и импорт

- «Поделиться» копирует ссылку `https://smaltra.github.io/soundix/#s=<данные>`. В данных весь набор: события, звуки из библиотеки по id, громкость, разброс, слова для поиска и макет, если его правили. Это JSON с версией формата внутри, сжатый `lz-string` (`compressToEncodedURIComponent`).
- Свои звуки в ссылку не входят. У получателя такие события помечены «нет звука».
- При открытии ссылки появляется вопрос: «Открыть набор из ссылки? Текущий заменится». Заменённый набор сохраняется как резервный, появляется тост «Вернуть прежний».
- «Импорт» принимает `soundix.json` из экспорта. Звуки библиотеки находятся по `source.library`, свои звуки получают пометку «нет звука». Если файл не подходит, показываем понятную ошибку, а текущий набор не трогаем.

## 7. Хранение

- localStorage, ключ `soundix:v1`: набор, избранное, макет, громкость прослушки, язык и резервный набор (с его макетом).
- IndexedDB через `idb-keyval`: свои звуки (Blob, имя, тип).
- Все обращения к хранилищам обёрнуты в try/catch. Без хранилища приложение работает, просто ничего не запоминает.
- Серверов, аккаунтов и аналитики нет.

## 8. Язык

EN и RU. Словари лежат в `src/i18n/en.ts` и `src/i18n/ru.ts`. Если язык браузера начинается с `ru`, интерфейс открывается на русском, иначе на английском. Переключатель в шапке, выбор запоминается.

## 9. Для агентов

- `public/llms.txt` описывает: что такое Soundix, где лежит `library.json` и какая у него схема, как скачать звук, как прочитать ссылку «Поделиться» (lz-string) и `soundix.json`. Там же сказано, что CLI появится вторым шагом.
- Вся логика живёт в `src/core/` и не зависит от браузера и React: модель набора, поиск и «Подходящие», транслит и имена файлов, кодирование и разбор ссылки, сборка и разбор `soundix.json`, сборка экспорта (список файлов архива и тексты Luau, JS, CREDITS, MD). Скачивание и ZIP — внешние адаптеры, в браузере это fetch и JSZip. На этот модуль потом опирается CLI.

## 10. Техника

- Vite + React + TypeScript в режиме strict. ES-модули, без точек с запятой (Prettier `semi: false`), маленькие функции.
- Зависимости: react, react-dom, jszip, idb-keyval, lz-string. Состояние держим в React (useReducer и context), без отдельных библиотек состояния.
- В `vite.config` задан `base: '/soundix/'`.
- 1372 строки в списке рендерятся без виртуализации. Если на слабом ноутбуке список тормозит, добавляем виртуализацию.

## 11. Тесты и проверка

- Vitest только для `src/core/`, каждое поведение проверяется один раз, без тестов на мелочи:
  - транслит и уникальные имена файлов;
  - «Подходящие»;
  - ссылка: закодировать и разобрать обратно;
  - макет: сборка из событий, JSON макета туда и обратно, ошибка разбора;
  - `soundix.json`: собрать, разобрать обратно, ошибки разбора;
  - экспорт трёх видов: список файлов, пропуск событий без звука, CREDITS только по использованным пакам, Luau и JS содержат все события.
- Интерфейс проверяется руками в браузере: Chrome, и Safari, если есть Mac. Проверить выбор звука, прослушку, макет, экспорт трёх видов (архив открывается, файлы играют), ссылку в другом профиле браузера, импорт и ширину телефона.

## 14. Не входит в v1

CLI и MCP (это шаг 2), экспорт под Unity и Godot, загрузка в Roblox из браузера, аккаунты и облако, аналитика, выравнивание громкости, обрезка и фейды, несколько наборов одновременно, случайный выбор из нескольких звуков на одно событие, звуки без лицензии CC0 (в том числе из Minecraft).

## 15. Шаг 2: CLI (после v1)

`npx soundix` (имя на npm свободно, публикует Scott):
- `search "<слова>"` — список звуков в JSON;
- `pull "<ссылка или soundix.json>" --format files|roblox|web [--ogg] --out <папка>` — то же, что экспорт на сайте; файлы скачиваются с Pages.

Потом `soundix mcp`. Основа — `src/core/`.
