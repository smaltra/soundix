# Soundix v2: дизайн

Дата: 2026-09-28. Решения Scott из чата. v2 заменяет ряд кнопок из v1 каркасом интерфейса (wireframe) и делает результат заданием для агента. Всё, что здесь не сказано, остаётся как в [дизайне v1](2026-09-28-soundix-design.md) (с его разделом 3.0 «Упрощение»).

## 1. Что это

Soundix — бесплатная веб-утилита для звуков Roblox-игры. Разработчик набрасывает каркас своего интерфейса (кнопки, окна, надписи) или получает его JSON от агента, заводит события, подбирает к ним звуки из библиотеки CC0 или свои, сразу тыкает каркас и слышит звуки. На выходе ZIP: звуки и `soundix.json`, который он отдаёт агенту, а агент сам подключает звуки в игре.

Принципы v1 остаются: всё в браузере, без сервера, аккаунтов и аналитики; только CC0; просто и по-человечески, без сценариев, раундов и прочей логики.

## 2. Экран

Шапка и три колонки: события, холст, панель справа. Шапка как в v1 после упрощения: Soundix, громкость прослушки, «Поделиться», «Экспорт», меню «⋯» (Импорт, «Промпт для агента», О звуках).

Интерфейс только на английском (решение Scott): переключателя языка и русского словаря нет. Имена событий по-русски вводить можно, ID всё равно транслитерируется.

Отмена правок набора и каркаса: Ctrl+Z / Cmd+Z, повтор — Ctrl+Shift+Z / Cmd+Shift+Z и Ctrl+Y (решение Scott). Набор текста в одном поле (от фокуса до ухода из него), одно перетаскивание или один жест ползунка — один шаг; шаги разделяются жестами, а не временем. Метка нетронутого примера отменяется вместе с набором. В текстовых полях работает их собственная отмена. Выделение, вкладки, избранное и громкость прослушки не отменяются.

### 2.1 События (слева)

Как в v1: название, имя файла (он же ID события), звук, громкость 0–100 %, разброс высоты 0–20 %, слова для поиска. Карточки в одну строку, настройки только у выбранного события. «+ Событие» добавляет любое событие, в том числе не про интерфейс: удар врага, машина, новый уровень. Такие события слышно кнопкой ▶ в карточке.

«Новый набор» предлагает «Пример» (раздел 5) и «Пустой». Прежний набор сохраняется как резервный, тост «Вернуть прежний».

### 2.2 Холст (в центре)

Холст 16:9 растягивается по ширине колонки. Координаты и размеры элементов хранятся долями холста (0–1), поэтому каркас масштабируется.

Сверху переключатель «Правка / Проверка» и в «Правке» кнопки «+ Кнопка», «+ Окно», «+ Надпись».

Элементы:

| Вид               | Что есть                                                                            | Срабатывания                     |
| ----------------- | ----------------------------------------------------------------------------------- | -------------------------------- |
| Кнопка            | ID, текст, эмодзи (по желанию), цвет, «Открывает: окно или ничего»                  | нажатие, наведение               |
| Переключатель     | ID, подпись, цвет                                                                   | изменение                        |
| Чекбокс           | ID, подпись, цвет                                                                   | изменение                        |
| Ползунок          | ID, подпись, цвет; каждый шаг                                                       | изменение                        |
| Поле ввода        | ID, подсказка (placeholder), цвет                                                   | фокус, ввод символа, Enter       |
| Выпадающий список | ID, варианты через запятую, цвет                                                    | открытие, выбор                  |
| Вкладки           | ID, названия через запятую, цвет                                                    | выбор                            |
| Окно              | ID, заголовок, цвет, содержимое «список» или «сетка», число моков (по умолчанию 12) | открытие, закрытие, выбор ячейки |
| Надпись           | ID, текст, эмодзи, цвет; для валюты, счётчиков, подписей                            | —                                |

Элементы окна (решение Scott после первого JSON от агента, где содержимое диалогов легло на главный экран): у любого элемента, кроме окна, есть `parent` — окно, в котором он лежит. Такой элемент виден только вместе со своим окном (в «Проверке» — когда окно открыто, в «Правке» — когда выбрано окно или элемент в нём). Кнопка внутри окна может закрывать его (`closes: true`). Моки показываются только в окнах без своих элементов. Удаление окна удаляет и его элементы. Soundix пишет `parent` у каждого элемента (`null` — на экране), поэтому свои файлы, ссылки и сохранённый набор не угадываются заново. Если в файле ни у одного элемента нет поля `parent`, Soundix раскладывает их сам: элемент попадает в последнее окно перед ним в файле, внутри которого лежит его центр; кнопка там с `closes: true`, которая играет `close` или называется Close/✕, закрывает окно.

JSON можно не только импортировать через меню, но и перетащить файл на страницу или вставить из буфера (Ctrl+V / Cmd+V вне текстовых полей, либо «⋯ → Paste JSON»).

Переключатель, чекбокс, ползунок, поле ввода, выпадающий список и вкладки добавлены по решению Scott, чтобы каркас покрывал обычные элементы интерфейса. В «Правке» новый элемент выбирается из списка «+ Add».

- Цвета — палитра прототипа: золотой, синий, зелёный, фиолетовый, красный, серый. Стиль игровой, как в v1: яркие объёмные кнопки. Эмодзи разрешены (решение Scott); на Windows 10 рисуются не все, это на совести автора каркаса.
- **Правка**: клик выделяет элемент, перетаскивание двигает, уголок меняет размер, шаг сетки 1 %. Окна в правке видны пунктирной рамкой поверх, чтобы не закрывать кнопки, и двигаются за заголовок. Delete удаляет выделенный элемент.
- **Проверка**: наведение мышью и нажатие играют звуки. Кнопка с «Открывает» открывает окно; открытие, ✕ и клик по ячейке окна играют свои звуки. Пока окно открыто, остальной экран размыт и затемнён (решение Scott), клик по нему закрывает окно со звуком закрытия. Окна скрыты, пока их не открыли, моки прокручиваются. Наведение работает только с мышью, на телефоне об этом подпись.
- Моки генерируются сами: в списке строки «Предмет 1…N» с числом, в сетке пронумерованные ячейки.

### 2.3 Панель справа

Две вкладки, открываются сами по последнему выбору:

- **Звук** — библиотека v1 для выбранного события: «Подходящие» и «Все звуки», поиск, фильтр по паку, избранное, свои звуки, клавиши ↑/↓, пробел, Enter, S.
- **Элемент** — свойства выделенного элемента из таблицы выше и выбор события на каждое срабатывание (или «без звука»). Кнопки «Дублировать» и «Удалить».

Новые элементы получают события по умолчанию — первое из списка, которое есть в наборе: нажатие `click`; наведение `hover`; изменение `toggle`, `click`; фокус `focus`, `click`; ввод `type`, `tick`, `click`; Enter `submit`, `select`, `click`; открытие `open`; закрытие `close`; выбор `select`, `click`. Переименование имени файла события переносит ссылки элементов. Если событие удалили, выбор пишет «нет события».

## 3. `soundix.json` версии 2

Один формат для экспорта, импорта, ссылки и агента:

```json
{
  "soundix": 2,
  "events": [
    {
      "id": "click",
      "name": "Клик",
      "file": "sounds/click.ogg",
      "volume": 0.8,
      "pitch": 0.05,
      "words": ["click", "tap"],
      "source": {
        "library": "ui-audio/click2",
        "pack": "UI Audio",
        "author": "Kenney",
        "license": "CC0",
        "url": "https://kenney.nl/assets/ui-audio"
      }
    }
  ],
  "ui": [
    {
      "id": "shop_button",
      "kind": "button",
      "text": "Shop",
      "emoji": "🛒",
      "color": "gold",
      "x": 0.02,
      "y": 0.1,
      "w": 0.09,
      "h": 0.15,
      "opens": "shop_window",
      "sounds": { "press": "click", "hover": "hover" }
    },
    {
      "id": "shop_window",
      "kind": "window",
      "text": "Shop",
      "color": "gold",
      "content": "grid",
      "items": 12,
      "x": 0.25,
      "y": 0.12,
      "w": 0.5,
      "h": 0.72,
      "sounds": { "open": "open", "close": "close", "select": "purchase" }
    },
    {
      "id": "coins",
      "kind": "label",
      "text": "1 250",
      "emoji": "💰",
      "color": "gold",
      "x": 0.02,
      "y": 0.72,
      "w": 0.18,
      "h": 0.07
    }
  ]
}
```

- `events[].file` — путь в архиве или `null`, если у события нет звука. `source` — как в v1: библиотека с автором и лицензией или `{ "own": true, "original": "my.wav" }`.
- `ui[].sounds` ссылается на `events[].id`. `opens` — ID окна. У окна `text` — заголовок.
- ID элементов и событий — `[a-z0-9_]`, уникальны каждый в своём списке, до 40 символов. По умолчанию ID элемента — транслит текста с суффиксом вида (`shop_button`), его можно поправить. Если назвать его как в игре (`shopbutton`), агенту проще.

Разбор (импорт, ссылка) строгий по форме и мягкий по значениям: не JSON, чужой формат, неизвестная версия, неизвестный `kind` у элемента или событие без `id` — понятная ошибка, текущий набор не меняется. Числа ограничиваются диапазонами, битые ссылки `opens` и `sounds` отбрасываются, повторяющиеся ID получают суффикс. Файлы v1 (`"soundix": 1`) импортируются: события берутся, каркас пустой.

Если в файле нет `events`, текущие события остаются, а каркас заменяется. События, на которые ссылаются элементы, но которых нет в наборе, создаются без звука. Так агент может прислать только `{ "soundix": 2, "ui": [...] }`.

## 4. Экспорт

Одно окно без выбора видов: формат «Оригинал» (по умолчанию) или «OGG (легче)», предупреждения, «Скачать ZIP» (доступно и без звуков: тогда в архиве только каркас, события с `file: null`, `CREDITS.txt` и `AGENT.md`). Архив `soundix-<дата>.zip`:

```
sounds/<id события>.<ext>   только события со звуком
soundix.json                весь набор: события (без звука — file: null) и каркас
CREDITS.txt                 паки из архива, как в v1
AGENT.md                    задание для агента
```

- Свои звуки идут как есть в обоих форматах; свой звук, которого нет в браузере, пропускается (как в v1 после ревью).
- Окно предупреждает о событиях без звука и о звуках в форматах, которых Roblox не принимает (mp3, ogg, wav, flac — можно).
- `AGENT.md` (английский) объясняет агенту задачу: загрузить файлы из `sounds/` в Roblox (Asset Manager или Creator Hub; ограничения на 2026-09-28: mp3/ogg/wav/flac, до 20 МБ и 7 минут, 100 загрузок за 30 дней без проверки личности и 2000 с проверкой — или попросить пользователя загрузить и прислать ID); сопоставить `ui[].id` с элементами GUI игры по именам и тексту, а при сомнении спросить; играть звук события на срабатываниях (`press` — Activated, `hover` — MouseEnter, `open`/`close` — окно стало видимым или скрытым, `select` — выбор ячейки); громкость `Sound.Volume = volume`, высота `PlaybackSpeed = 1 ± случайное до pitch`, один Sound на событие, `SoundService:PlayLocalSound`; события без интерфейса подключить там, где они происходят в игре, или спросить. Ниже в `AGENT.md` — таблица событий и элементов этого набора.

## 5. Пример

Лёгкий стартовый экран (решение Scott): кнопка Shop 🛒 слева вверху открывает окно Shop (сетка, выбор ячейки → `purchase`), кнопка ⚙️ справа вверху открывает окно Settings (список); слева внизу две валюты для вида — надписи 💰 1 250 и 💎 85 без звуков. Звуки уже выбраны, чтобы можно было сразу тыкать: `click`, `hover`, `open`, `close`, `select`, `purchase` и `hit` (удар врага — событие не про интерфейс). Пример — стартовый набор при первом входе.

## 6. Ссылка, хранение, агент

- «Поделиться»: как в v1, lz-string от `{ "soundix": 2, "events": [...], "ui": [...] }`, где у события вместо `file` и `source` поле `sound`: id звука библиотеки, `{ "own": "<имя файла>" }` или `null`. Свои звуки не переносятся.
- localStorage ключ `soundix:v3`: набор, каркас, избранное, громкость прослушки, резервный набор и версия примера. Пока пример никто не менял, при выходе новой версии примера он заменяется новым (иначе у вернувшихся посетителей остаётся старый). Если `soundix:v3` пуст, читается `soundix:v2` первой публичной версии как изменённый набор; не переносится только нетронутый старый пример: все поля событий и каркас совпадают с примером той версии (сравнение по отпечатку), нет резервного набора и избранного. Наборы из v1 не переносятся.
- «Промпт для агента» просит агента сохранить результат файлом `soundix-ui.json` (чистый JSON), а не выводить код в чат (решение Scott). Он в меню «⋯» и копирует готовый текст: «Опиши интерфейс моей Roblox-игры как Soundix JSON…» со схемой из раздела 3. `public/llms.txt` описывает библиотеку, ссылку, `soundix.json` v2 и этот промпт.

## 7. Что убираем из v1

Модули `UISounds.luau`/`ROBLOX.md` и `soundix.js`/`WEB.md`, выбор видов экспорта, наборы «Игра/Приложение», ряд кнопок «Проверить в деле» и его JSON, пэды (уже убраны).

## 8. Техника и тесты

Стек, структура и правила v1 остаются. Логика каркаса живёт в `src/core/` без браузера. Тесты Vitest только для `src/core/`, каждое поведение один раз:

- каркас: элементы по умолчанию, ID из текста и уникальность, переименование события переносит ссылки;
- `soundix.json` v2: собрать и разобрать обратно (события и каркас); файл только с `ui` создаёт недостающие события; импорт v1; ошибки (неизвестный `kind`, событие без `id`, чужой формат, версия);
- ссылка v2 туда и обратно, битая ссылка отклоняется;
- экспорт: список файлов, событие без звука (`file: null`, файла нет), отсутствующий свой звук, CREDITS по паку, `AGENT.md` содержит все события и элементы;
- остаются тесты v1 на имена файлов и «Подходящие».

Интерфейс проверяется руками в браузере: правка каркаса (добавить, двигать, менять размер, удалить), проверка (наведение, нажатие, окна, моки, прокрутка), выбор звуков, экспорт ZIP, ссылка, импорт JSON от агента, телефонная ширина.

- Экспорт даёт ZIP со звуками, `soundix.json` v2, `CREDITS.txt` и `AGENT.md`.
- `npm test` зелёный, сборка проходит, сайт публикуется тем же workflow после «да» Scott.
